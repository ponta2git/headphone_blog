## 成立した経路

`Markdown → Content Collections → remark → render() → 本文・一覧・description・RSS` を接続した。原稿の再解析で抜粋だけを取り出す処理や、独自キャッシュは追加していない。

- 原稿: 20220626、20231211、20240421、20250330、20250518の5記事。見出し階層を修正し、Info・WarningをNOTE・WARNINGへ、Postscriptを通常の文章へ変換した。
- 出力: 5記事、トップ、記事一覧、タグ一覧、4タグページの計12ページと `/rss.xml`。通常の `astro build` で静的生成する。
- 抜粋: 通常の段落・箇条書きから120 Unicodeコードポイント。切り詰めた場合のみ `…`。一覧・記事description・OGP・JSON-LD・RSSで同じ値を使う。
- 日付: 原稿と画面は暦日。RSS・OGP・JSON-LDはJST 0時。同じ記事のURL・GUIDは旧版と同じ。
- SEO: `.html`を含まないcanonical、正しいOGP寸法、`application/ld+json`形式。公開URLはレイアウトへ明示的に渡し、静的ファイル名から推測しない。
- OGP: 20240421で原稿の `ogImage` 明示指定を試し、それ以外は共通ロゴへフォールバック。本文画像からは推測しない。
- 表示: 本文幅最大768px、標準CSS、表・コードの横スクロール、見出しh1→h2→h3→h4。
- 操作: ネイティブbuttonによるコピーと結果通知、先頭へのスクロールとフォーカス移動。React・クライアント側フレームワークは使わない。

## 画像

代表記事の原画像3枚を `astro/src/content/posts/{year}/images/` に移し、原稿から相対参照する。旧 `public/images/posts/` は原画像への相対シンボリックリンクとした。Astroの公開画像ディレクトリも既存公開画像への相対リンクであり、編集する画像原本は一つ。

Astroと既存Next.jsの両方で、旧公開パスに出力されるファイルのSHA-256が工程1の値と一致した。リンクのまま公開出力されるのではなく、実ファイルとしてコピーされる。

| システム図 | 760×480   | 320 / 480 / 640 / 760                      |
| Clear Mg   | 2048×1536 | 320 / 480 / 640 / 800 / 1200 / 1600 / 2048 |
| E3         | 480×640   | 320 / 480                                  |

13種類の変換画像を生成。全srcsetのファイル実寸・縦横比・拡大抑制を検査した。`sizes`は本文幅に合わせて出力する。PCでの表示は順に760×480、768×576、480×640で、縦長画像を横長に変形したり拡大したりしない。

## 依存と交換箇所

| 場所                                                   | 責務と依存                                                                                                |
| ------------------------------------------------------ | --------------------------------------------------------------------------------------------------------- |
| `src/content/posts/`                                   | 通常のMarkdown、暦日、タグ、相対画像参照。Astro部品・レイアウト・生成URLを含まない                        |
| `src/lib/blog.ts`                                      | 日付・URL・選定・検証。Astroなしで実行できる                                                              |
| `src/lib/markdown.ts`                                  | Markdown ASTからの抜粋と標準的なHTMLへの補足。remark/unifiedへ依存し、Astroのモジュールや型には依存しない |
| `src/content.config.ts`、`src/lib/posts.ts`            | AstroのContent Collections・schema・render接続。別SSGへ移す場合の交換箇所                                 |
| `.astro`、`src/pages/rss.xml.ts`、`astro.config.mjs`   | テンプレート・ルート・RSS・画像生成。別SSGへ移す場合の交換箇所                                            |
| `src/scripts/interactions.ts`、`src/styles/global.css` | 標準DOMとCSS。Astroなしで再利用可能                                                                       |

ブログ規則とブラウザー操作にAstroをimportしない制約をESLintで検査する。汎用アダプターや独自レンダラーは設けていない。

Astro 7.4.7、ESLint 10.14.0、Prettier 3.9.10と対応プラグインを導入した。試作とNext.jsはロックファイルも独立させ、旧アクセシビリティプラグインのpeer依存が混ざる問題を解消した。型検査には互換性を確認した `@emnapi/runtime` 1.11.3を明示した。詳細なコマンドは[現在のREADME](../../README.md)に記載。

remarkプラグインのコード変更がContent Layerキャッシュへ自動反映されない場合があったため、規則変更後は `pnpm --dir astro build --force` を使う。標準機能によるキャッシュ更新で対応し、独自キャッシュは加えていない。
