## 2. 維持する仕様

| 項目        | 移行後の条件                                                                                                                                                         |
| ----------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 公開形態    | Astroで完全SSG。Vercelで静的配信。通常の閲覧にサーバー実行を必要としない                                                                                             |
| URL         | 通常ページ48件のURLを維持。記事は`/posts/yyyyMMdd`、タグは既存slug。ルート以外のcanonicalは末尾スラッシュなし。実ファイルの配置や拡張子には依存させない              |
| 記事情報    | タイトル、公開日、タグの意味と順序、本文の内容、リンク先、画像の内容と代替テキストを維持。誤ったリンクは下記の既知不具合として修正する                               |
| 日付とID    | 公開日は`YYYY-MM-DD`の暦日文字列。そこから`yyyyMMdd`のURLを決める。原稿の配置変更でURLを変えない。無効な日付、ID重複、ファイル名と日付の不一致、未知のタグを検出する |
| 一覧        | 新着は公開日の降順5件。全記事・タグ・感想・考察も降順。感想は「試聴」または「購入」、考察は「雑談」のタグで選ぶ                                                      |
| 前後・関連  | 前後は公開日の直前・直後。関連記事は自分を除き、タグが1つ以上共通する記事を新しい順に最大5件                                                                         |
| RSS         | `/rss.xml`、最新5件、既存項目のlink・GUID・公開日時を維持。説明文の抜粋化は意図的な変更として許容                                                                    |
| 日付の出力  | 画面は暦日のまま。現行RSSのpubDateは同じ暦日の`00:00:00 GMT`。移行でJSTの0時へ変換して9時間ずらさない。OGP・JSON-LDの公開日は現行の`+09:00`表現を記録している        |
| SEO         | サイト名を含むページtitle、ページごとのcanonical、description、OGP、構造化データを出力。旧実装の誤った形式・画像寸法は維持しない                                     |
| 公開画像URL | 元画像を移動しても既存の`/images/...`参照を壊さない。原画像の編集元は一本化する                                                                                      |
| 操作・計測  | URLコピー、上へ戻る操作、共有リンク、GTMを維持。操作失敗時の通知やキーボード操作は改善可能                                                                           |

サイトマップは全公開ページを対象にし、404等は含めない。標準出力名が変わる場合は旧`/sitemap.xml`からの恒久転送と`robots.txt`を同時に整える。更新日不明のページへ、ビルド日を最終更新日として設定する必要はない。

## 3. 意図的に変更する仕様

- MDXをMarkdownへ変換。原稿内にAstroの部品やレイアウトパスを書かない。
- `Info`22箇所、`Warning`6箇所、`Postscript`12箇所を整理。通常の文章を基本とし、囲みが必要な箇所だけGitHub Alertsの`NOTE`・`WARNING`を使う。追記の本文と日付は残す。
- 記事タイトルをh1、本文の最上位をh2とし、見出しの親子関係を維持する。現在の暗黙の見出し変換は撤去する。
- 抜粋は次のルールへ揃える。旧抜粋との文字列一致は求めない。
- OGP画像の本文からの自動推測を廃止。明示指定がなければ共通画像を使う。
- 標準CSSへ移行し、文字組み・余白・記事幅・注意書き・表・操作部品の見た目を調整する。旧版とのピクセル一致は条件にしない。
- 画像の複数サイズと`srcset`・`sizes`をビルド時に生成する。元画像より大きく拡大しない。
- React、Next.js、Tailwind、MDX評価処理、独自記事キャッシュ、metagenを撤去。ESLint・PrettierはAstro環境で最新版とプラグインの互換性を確認して導入する。
- 不要な依存は削除するが、Luxon等の利用中の依存を減らすことだけを目的とした追加リファクタリングは必須にしない。

抜粋の確定ルール:

1. Markdownの同じ解析結果から、通常の段落・箇条書きの文章を出現順に抽出する。
2. リンクは表示文字列、強調は中の文字列、インラインコードは中の文字列を使う。見出し・画像・表・コードブロック・引用・Alertsは除外する。
3. ブロックの境界と連続する空白・改行を半角スペース1つにまとめ、前後をtrimする。日本語の文字間へ新たな空白を入れない。
4. 先頭120 Unicodeコードポイントを採用する。実際に切り詰めたときだけ末尾へ`…`を付ける。空になる記事は検出する。
5. 一覧・記事のdescription・RSSで同じ結果を使う。手入力の要約を必須にせず、抜粋専用の再解析や独自TTLキャッシュを追加しない。

このルールは移行時の挙動変更として記録したもの。現行はtextノードを区切りなしで連結し、UTF-16の120コード単位で切り、常に` ...`を付けている。旧テストには200文字を基準にする弱い検証があり、そのまま引き継がない。

## 6. 次工程の範囲と完了条件

次は、代表記事から本文・抜粋・画像・一覧・RSS・SEOまでを生成する小さなAstro実装を作る。基本CSSとコピー・上へ戻る操作もここで確認する。全記事移行は、この実装の成立を確認した後に行う。

- 通常の静的ビルドで本文・一覧・RSSへ同じ抜粋が出力され、画像の`srcset`・`sizes`と縦横比が正しい。
- 日付・URL・記事選定・抜粋の規則は、Astroを起動せずにテストできる。Astroの型や描画コンポーネントをこれらの処理へ漏らさない。
- 記事取得の接続は少数の関数にまとめる。汎用アダプター、独自レンダラー、別の画像変換基盤、独自TTLキャッシュは作らない。
- `.astro`テンプレート、Content Collectionsへの接続、ルート・画像・フィード生成は将来交換する部分として受け入れる。
- 最新ESLint・Prettier、Astro用設定、`astro check`、Vitestが使える。標準CSSで読みやすさを確認する。
- 将来Astroを外すときに交換する箇所を列挙できる。別のSSGを実装して証明する工程は設けない。

## 比較データの読み方と限界

`baseline.json`は今回の固定スナップショット。原稿のfrontmatterを読み、ローカルの`out/*.html`をHTMLパーサーで抽出し、XMLパーサーでRSS・サイトマップを記録した。画像寸法は元ファイルから取得した。出力を手入力で再現したものではない。

- `posts`: 全33記事の情報、旧抜粋、原稿・本文テキストのハッシュ、見出し・画像・リンク、前後・関連記事。
- `pages`: 通常48ページのURL、title、canonical、description、OGP画像、記事リンクの順序、JSON-LD形式。
- `assets`: 公開ファイルのサイズ・ハッシュ・画像寸法と使用状況。
- `feeds`: ローカル生成と公開中のRSS／サイトマップ。公開RSSの5項目は全項目一致、サイトマップはURL一覧一致を確認済み。
- `liveHttpChecks`: 公開先の代表URL、末尾スラッシュ転送、既知の404の確認結果。

ハッシュは比較元を特定するための記録であり、原稿変換後の合否条件にしない。`capturedAt`、RSSの`lastBuildDate`、現行サイトマップの生成日由来の`lastmod`も固定比較しない。公開サイト全体が比較元コミットと同じ版であることまでは検証していない。

全48URLへのHTTP疎通、ブラウザーでの外観・操作、GTMへの実イベント送信、Vercel設定の切り替え・復元は未実施。工程2以降の試作と最終Previewで確認する。
